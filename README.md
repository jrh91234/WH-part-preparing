# WH Part Picking

ระบบติดตามการจัดพาร์ทตามใบโอนย้าย (直接调拨单) ของแวร์เฮาส์ — บันทึกว่า **ใครจัดพาร์ทไหน ใช้เวลาเท่าไหร่** และสรุป **ต้องใช้กี่คนต่อกะ**

- **หน้าเว็บ:** https://jrh91234.github.io/WH-part-preparing/ (GitHub Pages)
- **ฐานข้อมูล:** Google Sheet ชื่อ `WH Part Picking` (ใน Google Drive ของเจ้าของระบบ)
- **Backend:** Google Apps Script (`appscript/`) — deploy อัตโนมัติด้วย GitHub Actions

---

## สิ่งที่ระบบทำได้

| ผู้ใช้ | ทำอะไรได้ |
|---|---|
| **พนักงาน (worker)** | Login ด้วยรหัสพนักงาน + PIN → เปิดจ๊อบ → กด **รับงาน** (เริ่มจับเวลา) → กด **เสร็จ** (บันทึกชื่อ + เวลา) หรือ **แจ้งปัญหา** |
| **หัวหน้า (leader)** | ทุกอย่างของพนักงาน + **สร้างจ๊อบ** จาก PDF / รูปถ่าย / กรอกเอง + ดู **สรุป** (Man-hour, Lead time, คนที่ต้องใช้) + ปลดงาน / เปิดรายการใหม่ |
| **ผู้ดูแล (admin)** | ทุกอย่าง + จัดการผู้ใช้ + ตั้งค่าสูตรคำนวณ + ลบจ๊อบที่ยังไม่เริ่ม |

กฎที่ระบบบังคับ:
- ชื่อคนจัดมาจาก **บัญชีที่ login** เท่านั้น พิมพ์ชื่อคนอื่นแทนไม่ได้
- เวลาใช้ **นาฬิกาของเซิร์ฟเวอร์ Google** ไม่ใช่เวลาบนมือถือ
- 1 คนทำได้ **ทีละ 1 รายการ** และ 1 รายการรับได้ **คนเดียว**
- พนักงานไม่มีสิทธิ์เปิด Google Sheet จึงแก้ข้อมูลย้อนหลังไม่ได้

## ตั้งค่าครั้งแรก (ทำครั้งเดียว)

### 1. อนุญาตสิทธิ์ + สร้าง Admin
1. เปิด Google Drive → ไฟล์ **WH Part Picking** (Google Sheet)
2. รอสักครู่จะมีเมนู **WH Picking** → กด **1) ตั้งค่าเริ่มต้น / สร้าง Admin**
3. Google จะขออนุญาต → **ดำเนินการต่อ** → เลือกบัญชี →
   ถ้าขึ้น "Google ยังไม่ได้ยืนยันแอปนี้" กด **ขั้นสูง → ไปที่ WH Part Picking** → **อนุญาต**
4. กดเมนูเดิมอีกครั้ง → ใส่รหัสพนักงาน, ชื่อ, PIN ของ Admin
5. จะได้ชีต `Users`, `Jobs`, `Lines`, `Settings` และโฟลเดอร์ใน Drive "WH Picking - ไฟล์ใบงาน"

> ถ้ายังไม่ทำขั้นนี้ หน้าเว็บจะเชื่อมต่อ API ไม่ได้ (Apps Script ต้องได้รับอนุญาตจากเจ้าของก่อน)

### 2. ตั้ง GitHub Secret สำหรับ deploy อัตโนมัติ
Secrets `APPS_SCRIPT_ID` และ `APPS_SCRIPT_DEPLOYMENT_ID` ตั้งไว้แล้ว เหลือ `CLASPRC_JSON` (ข้อมูล login ของ clasp) ให้รันบนเครื่องที่ login clasp ไว้:

```bash
gh secret set CLASPRC_JSON --repo jrh91234/WH-part-preparing < ~/.clasprc.json
```

### 3. เพิ่มพนักงาน
1. เปิดหน้าเว็บ → Login ด้วย Admin → เมนู **👥 ผู้ใช้** → เพิ่มทีละคน (รหัส, ชื่อ, สิทธิ์, PIN)
2. ส่งลิงก์หน้าเว็บให้พนักงาน (LINE กลุ่ม หรือ QR Code ติดหน้าแวร์เฮาส์)
3. บนมือถือ: เปิดลิงก์ → เมนูเบราว์เซอร์ → **"เพิ่มไปยังหน้าจอหลัก"**

## วิธีใช้งานประจำวัน

**หัวหน้า — สร้างจ๊อบ**
1. เมนู **➕ สร้างจ๊อบ** → **เลือกไฟล์ PDF** (ที่ export จาก Kingdee)
2. ระบบอ่านเลขที่เอกสาร + ทุกรายการให้อัตโนมัติ → ตรวจ → **บันทึกจ๊อบ**
3. มีแต่กระดาษ → **ถ่ายรูปใบงาน** (OCR — ต้องตรวจทุกช่อง) หรือ **กรอกเอง**
4. เอกสารเลขเดิมสร้างซ้ำไม่ได้

**พนักงาน — จัดพาร์ท**
1. เปิดจ๊อบ → รายการเรียงตาม **ตำแหน่งชั้นวาง** (ส่วนกลาง/公共区域 อยู่ท้าย)
2. ถึงชั้นวาง → **รับงาน ▶** → แถบสีม่วงด้านบนจับเวลา
3. หยิบครบ → **เสร็จ ✓**
4. ของไม่พอ / หาไม่เจอ → **⚠ ปัญหา** (หัวหน้าเปิดให้จัดใหม่ได้)
5. กดผิด → **ยกเลิก** (เวลาไม่ถูกบันทึก)

**หัวหน้า — ดูสรุป (📊)**
- เลือกช่วงวันที่ → Man-hour, Lead time, เวลาเฉลี่ยต่อรายการ, รายคน, รายจ๊อบ, ปัญหาที่แจ้ง
- **⬇ ดาวน์โหลด CSV** เปิดใน Excel ได้ (ภาษาไทยไม่เพี้ยน) หรือเปิด Google Sheet ทำ Pivot เอง

## สูตรคำนวณ "ใช้คนกี่คน"

| ตัวเลข | สูตร |
|---|---|
| เวลาต่อรายการ | เวลากด "เสร็จ" − เวลากด "รับงาน" |
| Man-hour รวม | ผลรวมเวลาทุกรายการ |
| Lead time ของจ๊อบ | เวลาเสร็จรายการสุดท้าย − เวลาเริ่มรายการแรก |
| เวลารอเริ่ม | เวลาเริ่มรายการแรก − เวลาที่สร้างจ๊อบ |
| **คนที่ต้องใช้ต่อกะ** | Man-minute ต่อวัน ÷ จำนวนกะ ÷ (นาทีทำงานต่อกะ × ประสิทธิภาพ) |
| อัตราใช้งานคน | Man-minute ต่อวัน ÷ (คนต่อกะ × จำนวนกะ × นาทีทำงานต่อกะ) |

ค่าตั้งต้น (Admin แก้ได้ท้ายหน้า 📊 สรุป): **450 นาที/กะ**, ประสิทธิภาพ **85%**, **2 กะ/วัน**, **4 คน/กะ**

> เวลาที่วัดคือช่วง "รับงาน → เสร็จ" ไม่รวมเวลาเดินระหว่างจ๊อบ / รอของ — ค่า "ประสิทธิภาพ" มีไว้ชดเชย
> ควรเก็บข้อมูลจริง 2–4 สัปดาห์แล้วปรับค่านี้ก่อนใช้ตัดสินใจเรื่องกำลังคน

## การพัฒนาและ deploy

- **แก้หน้าเว็บ** (`index.html`, `css/`, `js/`) → push ขึ้น `main` → GitHub Pages อัปเดตเองใน 1–2 นาที
- **แก้ backend** (`appscript/`) → push ขึ้น `main` → GitHub Actions รัน `clasp push` + `clasp deploy` ไปที่ deployment เดิม (URL ไม่เปลี่ยน)
- **ทดสอบบนเครื่อง** (ไม่ต้องมี Google): `node dev/serve.js` แล้วเปิด http://localhost:5178
  ระบบจำลองรัน `appscript/code.gs` จริงในเบราว์เซอร์ (บัญชีทดสอบดูใน `dev/serve.js`)

## การดูแลระบบ

- **สำรองข้อมูล:** Google Sheet มีประวัติเวอร์ชัน (ไฟล์ → ประวัติเวอร์ชัน) + แนะนำ **ทำสำเนา** เก็บทุกเดือน
- **ข้อมูลเยอะ:** ~500 รายการ/วัน ≈ 150,000 แถว/ปี ยังใช้ได้ ถ้าเริ่มช้าให้ย้ายแถวเก่าใน `Lines`/`Jobs` ไปไฟล์อื่นปีละครั้ง
- **ลืม PIN:** Admin → 👥 ผู้ใช้ → แก้ไข → ใส่ PIN ใหม่
- **พนักงานลาออก:** แก้ไข → เอาติ๊ก "เปิดใช้งาน" ออก (ข้อมูลเก่ายังอยู่)
- **ห้ามแก้ชื่อหัวคอลัมน์ในชีต** (แถวที่ 1) และห้ามแก้ข้อมูลในชีตตรงๆ ระหว่างมีคนใช้งาน
- **ห้าม commit ไฟล์ใบงานจริง** (PDF/รูป) — repo เป็น Public (`.gitignore` กันไว้แล้ว)

## ข้อจำกัด

- กดปุ่มแล้วรอประมาณ 1–3 วินาที (ธรรมชาติของ Apps Script)
- หน้าจ๊อบรีเฟรชเองทุก 15 วินาที (ไม่ใช่ real-time)
- OCR จากรูปถ่ายแม่นน้อยกว่า PDF มาก ควรใช้ PDF จาก Kingdee เป็นหลัก
